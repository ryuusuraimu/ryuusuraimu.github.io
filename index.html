01 / INTERDISCIPLINARY SYNTHESIS & THE CORE PROBLEM

異なる分野の知識をつなぎ、課題の本質を捉える

私の強みは、異なる分野の知識や視点をつなぎ、ユーザー課題に対する新しいプロダクトの形を導き出せることです。
情報工学に加え、脳科学、認知心理学、哲学、マインドフルネスを幅広く学び、それぞれを個別の知識で終わらせず、「人はなぜそのように感じ、極限状態ではどのような環境なら無理なく行動できるのか」という人間の認知特性と行動原理からプロダクトを構想してきました。
この思想を具現化したのが、パニック発作時の支援を目的としたiOSアプリ「Anchor」です。本作は、Appleが主催する「Swift Student Challenge 2026」および「OpenAI Build Week」（Human Signalトラック）へ応募しました。

02 / HEARING & COGNITIVE LOAD PIVOT

当事者ヒアリングによる大転換：「沈黙」の解消

当初は呼吸ガイダンスやバイオフィードバックなど多機能を構想していましたが、当事者へのヒアリングと認知負荷の分析から、大きな方針転換を行いました。
激しいパニック発作（Autonomic Storm）の最中、人間の前頭葉機能・ワーキングメモリは著しく低下し、「画面のテキストを読む」「ボタンを選んで押す」「アプリの階層を行き来する」こと自体が深刻な認知的加害（Cognitive Harm）になります。
当事者が直面する最大の恐怖は、発作の身体症状そのもの以上に、必要な助けを周囲に一切伝えられない“沈黙”でした。

「発作が起きてから頑張るのではなく、平時に未来の自分のために準備する。」

そこで、平常時に支援内容や連絡先を完全に整えておき、有事の瞬間はスマートフォンが本人の代わりの声となる設計へと刷新しました。1アクションで画面全体が高コントラストな指示板（Shield）へと切り替わります。

03 / ARCHITECTURAL TENET // ZERO GENERATIVE AI IN PANIC

設計原則：なぜ発作の最中に生成AIを呼ばないのか

現代のプロダクト開発では安易に「AIがその場で励ます」設計が選ばれがちです。しかし、人命やパニック発作が関わるクリティカルな局面において、生成AIには3つの致命的な脆弱性が存在します：

01

ネットワーク遅延 (Latency)

1〜3秒のストリーミング遅延やスピナーの待機時間は、パニック下のユーザーに「動いていない」という強烈な不安と孤立感を増幅させます。

02

非決定論性 (Non-Deterministic)

発作の最中にハルシネーションや不適切なニュアンス、長文の語りかけが生じるリスクは絶対に許容できません。100%確定した言葉が必要です。

03

通信断 (Network Fragility)

地下鉄、飛行機、ビルの谷間、通信制限など、発作が起きやすい閉鎖空間ほど電波は不安定です。クラウド依存は救命設計になり得ません。

したがってAnchorでは、「AIは平時の準備（One-Minute Anchor）にのみ使い、有事は完全オフラインで決定論的（Deterministic）に実行する」という強固なアーキテクチャ境界を敷いています。
心が落ち着いている平時に、AI（GPT-4o / gpt-4o-mini-tts）とともに「未来の自分を救う言葉」を生成・吟味し、暗号化キャッシュとして端末に保存。発作が起きた瞬間は、生成AIもAPI通信も一切介さず、0ミリ秒でローカルキャッシュまたはiOS標準音声合成を叩く設計を貫きました。

04 / DUAL REPOSITORY EVOLUTION

2つのリポジトリ：プロトタイプから堅牢なシステムへ

SWIFT STUDENT CHALLENGE 2026

• Air-Gapped オフラインQR: QRコード内に外部リンクURLではなく、支援指示テキストを生データのまま内包。地下鉄・機内モードでも通行人のカメラで即座に読取可能。

• デュアル音声フォールバック: 事前生成されたOpenAI音声がある場合は即時再生。未生成・オフライン時はiOS標準の AVSpeechSynthesizer へシームレスに切替。

06 / MODERN SWIFT & ACCESSIBILITY FIRST

モダンSwift設計と徹底したアクセシビリティ

内部アーキテクチャには、iOS 17+の Observationフレームワーク（@Observable） と @MainActor を採用。不要なViewの再描画を完全に防ぎ、緊急時のバッテリー消費とCPU負荷を最小化しています。
また、アクセシビリティ要件として以下を徹底しています：

  • Dynamic Type対応: 端末の文字サイズ設定に完全連動し、拡大時もレイアウト崩れを起こさないFluid Layout。
  • Reduce Motion対応: 視覚過敏や前庭機能障害を持つユーザーに配慮し、不要なアニメーションを排除してフェードへ置換。
  • VoiceOver意味論ツリー: 画面が見えない状態でも、支援シールドの内容とQRコードの役割が音声で直感的に把握できるセマンティックマークアップ。

01 / BRAND STRATEGY // THE GOLDEN CIRCLE

サイモン・シネックのゴールデンサークルによる再定義

学生時代に最も情熱を注いだ米国向けPODアパレルブランド「Moftail」。
単なるグッズ販売ではなく、サイモン・シネックの『Golden Circle（Why → How → What）』の思考フレームワークを軸に、コミュニティの熱狂を生み出すブランド設計を一から行いました。

01 // WHY (信念・愛すべき不条理)

“Birdwatching is secretly the funniest hobby on Earth.”

「バードウォッチングは地球上で最も面白い趣味なのに、誰もそれを言葉にしてこなかった」。
朝4時に泥沼で迷彩服を着て「あれはオカヨシガモかマガモか」で激論を交わし、くしゃみひとつで一生に一度のライファー（初観察）を逃す――この愛すべき狂気と偏愛を肯定すること。

02 // HOW (差別化の仕組み・視点)

双眼鏡の内側からの視点 × 皮肉な対比

外野の嘲笑ではなく、ガチ勢が「わかる…！」と悶絶するインサイダーユーモア。
19世紀オーデュボン風の厳格な野鳥図鑑イラストや古典的タイポグラフィと、自虐的でキレのあるテキストを掛け合わせる知的で皮肉な対比。

03 // WHAT (具現化されたプロダクト)

身につけられるインサイドジョーク

• “Big Year, Small Budget”（全米探鳥の野望、資金は底をつく）
• “I Brake for Little Brown Jobs”（識別困難な小鳥LBJのため急ブレーキ）
• “eBird Made Me Do It”（eBird中毒に狂わされた人生）

02 / EVOLUTION // FROM ZEN ABSTRACT TO BIRDING OBSESSION

VER_1（抽象的な自然美・禅）の限界とピボットの必然性

最初からバードウォッチングだったわけではありません。初期仮説（VER_1_LEGACY）では、「日本の自然美と“今を生きる禅（Zen / Mindfulness）”思想」を掲げ、ヨガやストレス回復を志向するUS層向けのアパレルを展開していました。

「どれが一番綺麗か」ではなく、「どれが人を動かしたか」。
“Philosophy needs proof.”（思想には証明が必要だ）

しかし、実際にマーケットへぶつけて痛感したのは、「綺麗だけど、誰のものかわからない」という壁でした。抽象的な癒やしはコモディティ化しやすく、誰が誇りを持って身につけるのかという「所属意識（Belonging）」が生まれませんでした。
自らの主観の美意識を捨て、実際に人が強烈な偏愛と所属を持つコミュニティへ飛び込むため、世界で最も熱狂的かつ自虐的なBirding（野鳥観察）ニッチへの大転換を決断しました。

04 / BOTTLENECK DISCOVERY TO $30/H PAID CONTRACT

80件のカート追加と購入0の謎：テーマバグの特定と海外有償開発へ

監査を進める中で、不可解なデータに直面しました。80件ものカート追加（Add to Cart）が発生しているにもかかわらず、購入がゼロだったのです。
「単なるユーザーの迷い」で片付けず、ShopifyテーマのPDP（商品詳細ページ）をブラウザのDOM・イベントリスナー単位で徹底検証しました。
その結果、「初期ロード時にSサイズが視覚的に選択状態に見えるにもかかわらず、購入ボタンが無効化（disabled）され『Please select a size』と表示され続ける」という、テーマ内部のバリアント状態管理の重大な欠陥を発見しました。

サポートの「Shopify側の仕様です」を疑い、コードレベルの事実を突き止める。

この現象の再現手順、影響度、原因仮説、修正パッチ案を英語の構造化技術レポート（Notion）にまとめて海外テーマ開発元へ送付。調査の精緻さが開発元CEOに高く評価され、時給$30・14タスクの海外有償開発（Paid Client Trial）を受注することにつながりました。（※詳細はタブ03「BUILD MY POD」参照）

02 / 4-PART TECHNICAL REPORT

英語で文書化した4つの構造化レポート

01

再現手順 (Reproduction)

02

利用者への影響 (Impact)

サイズ変更時に価格が旧価格のまま表示されることで、購入者の混乱やカゴ落ち（コンバージョン損失）につながる事業リスクを提示。

03

原因仮説 (Hypothesis)

04

修正案 (Proposed Patch)

不具合を直接解消する修正コードスニペットとPR（Pull Request）の差分を添付。
